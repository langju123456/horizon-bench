# 已经读过原表，审阅人为什么还没收到稿？

上轮宁德时代全年题，模型读过交接和印刷页 11、12，却没有调用 `finish`。十二步里有八步没有工具动作，归档里这些步的可见文本也为空。我们能定位到提交没有发生，无法从这条记录判断模型当时在想什么。现场的问题是怎样让下一班自己交出可验收的正确报告。

## 推理前固定的选择

| 候选 | 采用条件或代价 | 本轮 |
|---|---|---|
| 1. 沿用全部工具与原提示 | 观察已有系统在相同机器上的表现 | 实测 auto |
| 2. 开工时直接说清提交的五个字段 | 每次多读一小段说明，可能帮助嵌套参数成形 | 实测 fields |
| 3. 第一次回复没有工具动作时，提醒一次交稿或继续取证 | 只在可能卡住时介入，已正确提交的路径无需提醒 | 实测 reminder |
| 4. 这一班只展示读交接、读原页、交稿三件工具 | 去掉笔记工具；多班次写交接时需要另外验证 | 实测 task_tools |
| 5. 根据已有证据阶段动态缩小工具菜单 | 需要可信的就绪判定，过早收紧会截断取证 | 待测 |
| 6. 在模型接口要求每步都产生工具调用 | 依赖服务端支持，可能换来无关调用 | 待测 |
| 7. 把最终提交拆成填写草稿和确认两步 | 更容易显示或纠错，增加一个动作 | 待测 |
| 8. 解析自由文本，先展示预填草稿供确认 | 适合确实有可见文本时，需验证漏字段与误解析 | 待测 |
| 9. 用只读引用代替重抄人工备注 | 保字面准确，引入引用解析的产品责任 | 待测 |
| 10. 从经人工复核的成功与失败轨迹训练模型 | 有望迁移到更多界面，需要留出任务验证权重收益 | 待测 |

四组选项独立使用。运行同一份本地 Qwen3‑8B，完整中文工具返回、完整交接、温度零、不启用思考、每题 12 步，每次最多 384 个输出 token，总预算 16,000、上下文预算 8,000、模型时间上限 240 秒。沿用运行器按动作边界检查累计预算的语义。每个方案各做宁德时代和中国铝业的两道反向改口径题，共十六次独立启动。旧基线只作历史参考。本轮先用参考脚本确认四题可解，再执行模型。第四组只改变提供给模型的工具菜单，仍由它选择来源和填写全部答案。

新文档也在运行前固定。中国铝业 2025 年报印刷页 **10** 有年度表，页 **11** 的季度表在同页含表头和数据。两页金额均为人民币千元。工具提供由原表摘列的文本。两题分别从全年改为第四季度、从第四季度改回全年，各有独立的人工编写交接和审阅备注。模型只见交接、页码清单和自己打开的原表。两家公司使用同一个提交 schema。新题用于测试跨发行人和表格布局，开发者能看答案，无法保证模型预训练时从未见过公开年报。[中国铝业年报，第 10 页](https://static.cninfo.com.cn/finalpage/2026-03-28/1225048106.PDF#page=10)

每题保留所有动作和费用统计。主判据为原有独立验收全部通过，含交接、读页、期间、金额、单位、引用、原备注及过程控制。单独列是否提交与正确交付，报告每组修复和退化的题，以及实际输入、输出和模型耗时。对四题的小样本逐题比较。若结果相同，优先保留在两种修改方向均能交付、兼容现有工具的最小改动。新文档只运行预先选定的四组，后续调参需再留新题。

## 复现

```bash
for strategy in auto fields reminder task_tools; do
  for doc in catl transfer; do
    env -u HB_API_KEY -u OPENAI_API_KEY hb --runs-dir runs/D005 run \
      --family annual_handoff --policy llm --name "D005-$doc" --tools rich --variant handoff_full \
      --handoff-doc "$doc" --submission "$strategy" --seeds 2 --horizon 12 --session-len 12 \
      --max-steps 12 --max-tokens-per-call 384 --max-total-tokens 16000 --context-budget 8000 \
      --wall-time 240 --temperature 0 --model qwen3:8b --base-url http://127.0.0.1:11434/v1 \
      --no-think --tool-observation unicode || exit 1
  done
done
python scripts/handoff_archive.py dump runs/D005/hb.sqlite runs/D005-traces D005-catl D005-transfer --study D005
python scripts/handoff_archive.py check runs/D005-traces --study D005 --reports-dir reports
```

## 实测与决定

**开工时写清五个字段，让收到稿件的题数从 2/4 增至 4/4，严格验收仍是 1/4。** 这组的四份稿都选对最新期间、金额、单位，保住审阅原话；其中三份把看过的另一张表也算作依据。按预登记，凡引用页组不精确仍判失败。使用者可以先采纳字段说明来减少漏交，给审阅人直送稿件还需要解决引用定位。

| 模型面对的交稿方式 | 成功提交 | 严格通过 | 4 题总模型调用 | 输入 / 输出 token | 累计模型耗时 |
|---|---:|---:|---:|---:|---:|
| 原提示和工具 | 2/4 | 1/4 | 36 | 40,768 / 1,901 | 230.4 秒 |
| 开工时写清五个字段 | 4/4 | 1/4 | 25 | 27,879 / 883 | 136.4 秒 |
| 第一次无工具动作后提醒 | 1/4 | 1/4 | 40 | 46,917 / 2,238 | 260.5 秒 |
| 只展示三件任务工具 | 3/4 | 1/4 | 26 | 24,294 / 1,285 | 161.0 秒 |

| 固定任务与应引印刷页 | 原提示 | 列字段 | 提醒一次 | 三件工具 |
|---|---|---|---|---|
| 宁德时代改为第四季，页 11、12 | 通过 | 通过 | 通过 | 通过 |
| 宁德时代改回全年，页 11 | 未提交 | 多引页 12 | 未提交 | 多引页 12 |
| 中国铝业改为第四季，页 11 | 多引页 10 | 多引页 10 | 未提交 | 多引页 10 |
| 中国铝业改回全年，页 10 | 未提交 | 多引页 11 | 未提交 | 未提交 |

**从用户输入复盘。** 中国铝业的交接先要求准备第四季度，再改为全年。列字段组读完交接和页 10、11，第一次调用提交工具时参数无效，随后重试，成功交出 **34,092,341 千元**和“审阅备注：保留人民币原单位。”。其中页 10 可核验全年，页 11 只有季度数，两页都写进了稿件。这份稿把漏交和引用精度两个问题分开了。[原始轨迹](../../reports/submission/traces/fields-dev3.json) · [原始年报，页 10](https://static.cninfo.com.cn/finalpage/2026-03-28/1225048106.PDF#page=10)

**读成绩时要知道的口径。** 原提示要求引用覆盖表头和数据行，验收还要求去掉多余页。十份有效提交中，六份都只败在多引了另一张已读表。若审阅人允许额外列出一张已经打开的背景页，这十份稿都会通过；这是看到结果后才做的敏感性分析。上表始终使用原判据。下一项要检验的是，把直接支撑数值的原格与读过的背景页分开后，能否在新文档上提高严格通过率。

模型为本机 Ollama 的 Qwen3‑8B Q4_K_M，指纹 `500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`。四题的种子 0、1 对应宁德时代，2、3 对应中国铝业；各取季度、全年两个方向。十六个任务都在冻结提交后重新运行，共 **127 次真实模型调用**，另有四条规则脚本参考成功。没有外部模型调用费。提醒在三题实际触发，这三题都未交稿。精简菜单也同时缩短了输入，现有数据只能比较这一整套配置。本机还在处理其他任务，耗时供复盘。所有动作和判定可离线重放，四道独特任务不足以估计上线成功率。[冻结设计](https://github.com/langju123456/horizon-bench/commit/4e200ff) · [16 条轨迹](../../reports/submission/traces) · [逐题复盘页](../../reports/submission/review.html)
