# 上一班改过报告口径，下一班该带走哪些信息？

分析师最初要全年值，后来改要第四季度，审阅人还要求原样保留一句话。另一份任务的修改顺序相反。收件人拿到最终数字时，应能打开对应来源，也能看到那句手改的话。这决定交班时哪些信息值得占用上下文。

| 我会让下一班看到什么 | 代价和可能遗漏的东西 | 首轮 |
|---|---|---|
| 1. 只传最后一条事件 | 便宜；要求可能在更早的消息里 | 实测 |
| 2. 传最近三条事件 | 实现简单；结果依赖消息顺序 | 实测 |
| 3. 在统一的交接长度上限内带原始历史 | 保留原话；新旧口径会同时出现 | 实测 |
| 4. 按公开事件类型维护当前口径与受保护的原话卡片 | 节省读取量；要求系统正确识别和记录变更类型 | 实测 |
| 5. 上一班的模型写自由文本摘要 | 多一次生成，可能改写人写的话 | 未测 |
| 6. 下一班按关键词回查原消息 | 要挑关键词，可能只召回旧口径 | 未测 |
| 7. 用向量召回语义相近的历史 | 要模型和索引，相似的新旧请求容易混淆 | 未测 |
| 8. 交付初稿与逐版本差异 | 能看到改了什么，需要完整版本链 | 未测 |
| 9. 单列仍有效的约束，由审阅人交班前确认 | 能反映人当前意图，依赖审阅人当班 | 未测 |
| 10. 当场回问不确定的一项，再交付 | 有助于消除歧义，需要用户在线 | 未测 |

**预登记。** Codex 提出备选并代跑。首轮选择四种本机可实现的策略，分别检验最近事件、小窗口、原始历史和类型化记录。每种策略都用同一对相反方向的公开开发任务、相同原始事件、原表摘录、工具和模型。交接接口只读已对操作者公开的记录。类型化事件已经存在于模拟系统，抽取真实自然语言需求的成本需要另测。

**预算和读数。** 固定本地 Qwen3 8B、温度 0，单任务最多 12 步、每次最多 384 个生成 token、总计上限 16000 token（调用前检查，最后一次调用的实际用量单列）。四组都使用相同的请求上下文预算和交接文本上限，实际保留的文本长度可以不同。上一班的修改历史固定回放，下一班由模型自行调用工具查资料、选择期间并交报告。规则参考控制器的结果单列。两条任务共同使用一份公开年报，只能作为开发样例。

**验收。** 每次核对实际提交的产物、最新期间、金额、单位、来源页、实际读取来源的动作、应逐字保留的审阅内容。另报模型调用数、输入输出 token、耗时、失败理由与原始动作回放是否一致。小样本计数相同时，保留平局。外部收件回执由第一项实验独立评估。

宁德时代 2025 年报在印刷页 11 披露全年现金流，分季度表的表头在页 11、数据行在页 12。任务工具提供标有这些页码的人工核过的摘录。[原始年报](https://static.cninfo.com.cn/finalpage/2026-03-09/1225002666.PDF)

## 在本机重复这批正式比较

从仓库根目录运行。安装项目、启动本地 Ollama 并已有 `qwen3:8b` 后，使用同一模型依次完成四组。每段交接最多 600 个字符，每任务最多 240 秒累计模型耗时。总用量和时间在发起下一次调用前检查。这里的“正式比较”指按本页条件记录公开开发样例。

```bash
for mode in handoff_full handoff_last handoff_card handoff_recent3; do
  env -u HB_API_KEY -u OPENAI_API_KEY hb --runs-dir runs/D002 run \
    --family annual_handoff --policy llm --name D002 --tools rich --variant "$mode" \
    --seeds 2 --horizon 12 --session-len 12 --max-steps 12 --max-tokens-per-call 384 \
    --max-total-tokens 16000 --context-budget 8000 --wall-time 240 --temperature 0 \
    --model qwen3:8b --base-url http://127.0.0.1:11434/v1 --no-think || break
done
python scripts/handoff_archive.py dump runs/D002/hb.sqlite runs/D002-published D002
hb --runs-dir runs/D002 report --name D002
```

用 `python scripts/handoff_archive.py check <轨迹目录>` 可离线逐步重放。归档工具核对八个实验格、预算、模型标识、记录的模型用量、工具返回和最终判定。重放使用历史动作，不产生新的模型调用。各任务的规则控制器可用 `--policy catalog` 单独运行。

## 实测结果

机器为 Apple M4、24 GiB，使用本机 Ollama 的 `qwen3:8b`、Q4_K_M，模型指纹 `500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`。八次运行串行，模型时间为两题调用耗时之和。没有外部 API 账单。墙钟含当时 Mac 上其他活动，不能据此预测部署延时。

| 交接方式 | 规则控制器 | Qwen3‑8B | 两题模型调用 | 输入 / 输出 token | 两题模型时间 |
|---|---:|---:|---:|---:|---:|
| 最后一条 | 0/2 | 0/2 | 22 | 32,454 / 1,220 | 220.3 秒 |
| 最近三条 | 1/2 | 0/2 | 22 | 34,580 / 1,198 | 248.2 秒 |
| 全历史 | 2/2 | 0/2 | 16 | 27,943 / 846 | 224.9 秒 |
| 结构卡 | 2/2 | 0/2 | 14 | 19,257 / 811 | 165.8 秒 |

参考控制器在看不到审阅句时停下。把审阅句移到窗口之外，最近三条就会从通过变为失败。八条真实模型运行全部未通过；其中五条在下一步开始时耗尽 token 预算。结构卡的季度题保住了审阅原话，模型也确实打开两页，却仍选了全年值。全历史同一题还把“千元”抄成“千万元”。这次没有依据宣布哪种记忆提高了模型的交付率。
