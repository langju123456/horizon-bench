# 审阅人批准了第二版，收件人手上的究竟是哪一版？

ForgeFlow 的 Apple 公开案例保留了退回的第一版、批准并本地交付的第二版、版本摘要和事件。HorizonBench 可拿同一份归档，用自己的本地模拟收件箱检查下游实际出现的效果。上游原档按其发布提交固定；实验收件是下游另一次受控运行。原始财务问题的评分由 EvidenceLoop 负责。

| 我可以凭什么签收 | 可能漏掉什么 | 首轮 |
|---|---|---|
| 1. 看出件界面的“已交付” | 下游可能没收到 | 实测 |
| 2. 核实上游文件指纹、批准事件和本地回执 | 核实了该发哪版，下游份数仍未知 | 实测 |
| 3. 给收件箱数份数，正好一份就签收 | 唯一一份也可能是旧稿 | 实测 |
| 4. 核实批准链，再读收件箱核对任务、份数、版本和实际内容 | 需要有权限查下游 | 实测 |
| 5. 让收件人逐页和审批稿对照 | 时间长，需要人到场 | 未测 |
| 6. 核对收件方签名的内容摘要 | 需要可信签名及密钥管理 | 未测 |
| 7. 收件端回调确认任务和版本 | 回调也可能丢失或重发 | 未测 |
| 8. 批量比对出件与收件账本 | 便宜，但发现错误会晚 | 未测 |
| 9. 对唯一交付编号查询状态 | 必须验证编号确实绑定该报告 | 未测 |
| 10. 比对导出 HTML 和机器稿中的关键字段 | 能发现两种格式内容不一致，仍需覆盖真实收件 | 未测 |

**预登记。** 四种检查都看同一个固定的开发稿，使用同样的上游归档与模拟收件数据，各自在自己声明的观察范围内决定签收。受控场景为：收到获批第二版一次、收件箱为空、两次收到第二版、只收到被退回的第一版，以及上游导出的批准摘要损坏但下游恰有一份原第二版。只有第一种应签收；第五种应等待上游澄清。检查能否放行正确交付，同时拦住漏件、重复、旧版和损坏的批准依据。提供逐格判定与误收数量，不将五种情形当作线上发生频率。

此项由 Codex 代做。实验端复用 D001 的 SQLite 收件箱，在独立临时目录建每个场景。输入的公司、草稿、版本、批准内容摘要和文件来源可回溯到同一个上游案例；上游模拟身份、工具与实际模型调用数沿用原记录。

## 一份真实本地审批稿的五种下游结果

固定上游 ForgeFlow 提交 `b74c8bb439658d1530a762391e13ae1861bd8968`，从该 Git 对象读三个原文件，核对清单及两份稿件的字节指纹、任务和运行编号、版本父链、模拟审阅角色、批准内容摘要、交付事件与本地回执。上游记载它通过本地 FastAPI 和 SQLite 执行，作者和审阅人由脚本扮演，模型调用为 0；本实验核过归档内的请求编号和事件，模型用量沿用上游披露。[原始提交](https://github.com/langju123456/forgeflow/commit/b74c8bb439658d1530a762391e13ae1861bd8968)

| 检查办法 | 正常一份 | 漏件 | 重复两份 | 唯一一份是退回版 | 出示的批准依据损坏 | 正确判断 |
|---|---|---|---|---|---|---:|
| 看出件状态 | 签收 | 误收 | 误收 | 误收 | 误收 | 1/5 |
| 核上游批准链 | 签收 | 误收 | 误收 | 误收 | 挂起 | 2/5 |
| 只数收件份数 | 签收 | 挂起 | 挂起 | 误收 | 误收 | 3/5 |
| 核准版本再查收件 | 签收 | 挂起 | 挂起 | 挂起 | 挂起 | 5/5 |

推荐第四种用于需要确认交付的任务。在这个案例，出件方的回执在“漏件”和“下游收两次”时完全一样。仅数份数又会把退回的第一版当作交付。项目的两个 SQLite 场景是本机模拟；真实企业外部收件服务需提供同等的观察接口，才能在实际业务里做这项核对。

结果保留上游 case_id、draft_id、两个工具运行编号、版本摘要、本地回执与五种模拟收件。第二版业务内容摘要以 `04e775dc` 开头。关闭模型服务也能重做这个实验。[20 格逐项结果](../../reports/forgeflow-delivery/matrix.json)

```bash
hb forgeflow-delivery --source-repo ../forgeflow \
  --source-commit b74c8bb439658d1530a762391e13ae1861bd8968 \
  --review-sha256 94b062fd35b1fc20822d7cca9a645f9b7f4cd109acc5f06ec5c8247f61adb70e \
  --output /tmp/forgeflow-delivery-result.json
```

`--source-repo` 指向含上述提交的 ForgeFlow 检出目录。命令只读取 Git 对象，可以从其他分支运行。输出文件使用新路径。
