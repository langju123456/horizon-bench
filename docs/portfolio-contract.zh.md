# 年报 Agent 三项目长期约定

给分析师和审阅人做一份能签收的经营报告。分析师要能找原始数字、改问题、保留手改部分，审阅人要能看到改动并批准具体版本。断线后回来，应能弄清报告有没有真的送达。下一期可以沿用指标定义，所有数字重新取证。

## 工作分给谁

| 仓库 | 负责的问题 | 看什么才算交付 |
|---|---|---|
| ForgeFlow | 使用者能否在真实报表上完成工作？ | 从任务、检索、工具、计算、局部修订、审批到导出；原始单元格与公式可回查；真实模型和替身的容量实验各有机器、负载与分母。 |
| HorizonBench | 同样的任务给不同策略，遇到同样的意外，谁还能完成？ | 固定任务包、种子、预算和故障；用独立的最终产物与外部效果判定；按历史动作回放并指出首个差异。旧反应器仍是连续状态变化的对照环境。 |
| EvidenceLoop | 哪类错误值得修，改动是否有用？ | 原表与原始轨迹相连，能识别错期、错行、错单位和错误审批；按文档族拆分数据，报告修好、退化和成本；训练要能加载权重，在独立留出任务上比较。 |

交换材料标注版本、case_id、run_id、模型与工具版本、证据来源、动作、产物标识和内容哈希、分项判定、等待时间与用量。每个系统拥有自己的业务事实；只交换可复核的引用和必要数据。新会话先读本约定、项目的实验记录、当前 Git 状态与最近提交，再认领下一个未完成切片。

## 要服务的岗位

企业 Agent 与全栈岗看任务交付、用户能否改稿、RAG、工具、队列与故障定位；Harness/Runtime 岗看规划、上下文、Skills、MCP、子 Agent 与恢复对照；评测岗看数据、独立验收、人工校准、误判及回归；算法岗看 SFT、偏好或奖励实验、推理效率与泛化证据。具身仿真、内容生成、支付式一致性各自保留专门实验。招聘联系人、薪酬和个人数据留在私人求职资料里。

## 每次核心选择都留下经验

1. 用一句话说清「我作为使用者需要决定什么，选错有什么后果」。
2. 从用户视角列十种有实际区别的办法，说明依赖、代价和可能出错的情形。记录谁提出、谁实施、谁确认。Codex 代做的实验由 Codex 署明。
3. 在看成绩前挑三至四种便宜、有代表性且能区分关键假设的办法，固定输入、预算、成功判据。其余记为未测。
4. 真跑。给原始记录和复跑命令，分别报修好、退化、成本、异常，以及结论在什么情形下可能反转。若证据分不出胜负，保留这个结论。
5. 一个可独立核验的切片做一个 Git 提交。中文标题讲解决了什么小问题，正文讲为什么、怎么验、结果与边界。下一步引用已提交证据。常规机械改动按正常测试处理。

## 进度从哪里接

公开开发样例使用宁德时代 2025 经营现金流全年/季度混淆，以及 Apple FY2025 服务增速/增量贡献。它们可以复盘，正式留出集使用其他预先封存的任务。

工业反应器基线保留了持续扰动下的控制、检查点和回放。年报环境沿用同一个运行器，用最终报告和收件人的记录验收信息工作。
